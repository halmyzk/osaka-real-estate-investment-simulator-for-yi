# Gate A/B 計算エンジン受入準備・差分管理（開発専用）

ステータス：**検証拡充中／Gate A・B全体の受入未完了／公開未承認**。

## 今回確認した事項

- `src/acceptance.mjs` の `auditOperatingVAT` は、月次営業モデルの宿泊・賃貸売上、宿泊・賃貸・保有費、借上賃料、更新CapExを**純額の費目ごとに**請求書明細と突合する。請求書ID重複、費目不明、課税区分不整合、税込金額の不一致、明細欠損は例外。
- `auditTaxCompleteness` は納税主体×年度ごとの所得、資産、消費税、現金納税の4領域を確認。未設定は `incomplete`、仮定依存なら `estimated`。
- 既存 `src/vat-cash.mjs` は、元のネットP/L現金を除外したことが明示されない場合は、税込取引CFの上乗せを拒否する。**照合済みという事実だけで、元CFから自動的に金額を差し替える機能はない。** 照合とブリッジの統合、自動リンクは次の課題。
- GitHub Actions はPython JSON Schema検証とNode.js全テストを実行する。**テスト成功は個別設計の実装合格であり、法律上の申告精度を保証しない。**

## 判定規則

1. **計算数値が出た**と**適用税務ルールが確定した**を別ステータスにする。
2. 不足は0・税額還付・住宅売却特例に置き換えない。
3. `main`および公開`index.html`に変更を加えない。開発ブランチで全受入とレビュー後、別途公開承認を求める。
4. 残る課題を全テスト合格という表現で覆い隠さない。
