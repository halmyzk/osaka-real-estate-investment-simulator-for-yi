# v1.1 投資判断用「概算税引後投資評価」モード

更新：2026-10-14 JST
実装ブランチ：`develop/v1.1-foundation`
適用判断：ユーザーは **「実際の税務申告に使用できる精度は求めない。不確定な事項が多いなか概算的な財務分析ができればよい」** と明示した。

## 1. 目的・変更点

完成条件を「各納税者の税務申告を正確に再現」ではなく、**不明な税務条件を入力可能な仮定として保存・再利用し、宿泊・賃貸・自己居住・購入売却・融資から概算税引後CF/NPV/IRRを比較する**こととする。

Gate Bの厳密な税務元帳・レビュー済み証拠ルートは引き続き独立させる。新しい**概算モードは別のシミュレーション経路**であり、正式な`afterTax`と区別する`indicativeAfterTax`を返す。財務意思決定用の概算NPV/IRRは表示してよいが、税務申告用の税額や特例適格性を証明したと表示しない。

ユーザーが既存の「税額0円」と「未計算」を混同しないよう、**概算モデルを明示的に有効化する前は`indicativeAfterTax:null`**。有効化すると全ての採用仮定を実データに紐付けて明細表示する。

## 3. 現金CFへの接続

既存の営業CFは「**売上・経常仕入費用を税抜で入力した**」と仮定する。購入価格・売却価格・その他投資CFは**ユーザー入力そのまま**とし、税額を勝手に上乗せ・還付しない（必要なら後でVAT課税取引別の詳細モデルに切り替える）。

```text
VAT output cash collected at month m
    = Modelled taxable lodging revenue * UserVatRate   (only registered entity)

Supplier VAT paid at month m
    = LodgingOperatingCosts * VATTaxableFraction[lodging] * UserVatRate
    + RentalOperatingCosts * VATTaxableFraction[rental] * UserVatRate
    + PropertyOperatingCosts * VATTaxableFraction[property] * UserVatRate

Provisional credit = (Lodging vendor VAT +
  Shared-property vendor VAT * M3 business-use share) * UserCreditEligibilityFactor
Credit actually applied = min(OutputVAT, ProvisionalCredit)
VAT cash settlement next year = -max(0, OutputVAT - CreditApplied)

Operating cash adjustment = OutputVAT collected - SupplierVAT paid
                            + VAT settlement cash
Estimated after-tax CF = Pre-tax Equity CF + Operating VAT cash adjustment
                         - Personal/Corporate/Sale-income cash taxes
```

**VAT仕入の仕入税額控除や還付は正確な税法判定ではない**。免税・課税の状態は主体ごとに明示選択する。住宅賃貸の売上は非課税供給とする簡易仮定。借上住宅賃料は消費税対象外とするが、賃貸運営・共通運営の仕入税額は相手の仕入内容に応じて編集する。未確定の免税や還付をプラスCFにはしない。

### 推計所得税・減価償却と売却益

- 所得区分はM1宿泊＝事業所得、M2/M3宿泊＝雑所得、M2/M4住宅賃貸＝不動産所得、法人は法人通常所得の**モデル初期仮定**。同一主体内の種類別赤字を他の個人所得に自動通算しない。
- 経常仕入費用に支払うVATのうち事業関連部分の非控除分は、概算通常所得における費用に加える。貸付・借入元本は必要経費としない。借入利息は年次支払と事業用割合で仮定。
- 建物取得費：個別資産台帳に土地・建物があればその原価、なければ**購入価格×ユーザー設定の建物割合**を使用。土地は償却しない。建物は**年率・期間・事業用面積割合**から概算償却し、残存簿価を最低1円とする。法定耐用年数・本来の私用建物譲渡時減価相当額の適格性を保証しない。
- 出口税：売却総額－売却費－概算調整後取得費。譲渡損は勝手に通常所得に損益通算しない。個人の短期／長期（保有年数）に対応する**編集可能な仮の合算税率**で分離課税を概算。法人所有の売却益は法人通常所得に一度だけ算入する。住宅譲渡特例の減額は自動利用しない。
- 追加所得課税：年次で所得区分ごとのプラス所得に概算実効税率を掛ける。個人は翌年3月に国税分、住民税相当分は翌年6/8/10月・翌々年1月に4等分。法人は翌年2月払い。**日付は予測上の便宜的スケジュールで、実際の納期限ではない**。
- 消費税、法人・個人所得税、個人譲渡税の税負担は**現金納付が生じる暦年**で反映し、退出後の納税を2026年の営業CF等へ無理に振り替えない。

## 4. 初期設定は固定法定税率ではない

編集可能なデフォルトは以下。これらは金融モデリング用であり、税率・減価償却の法律上の適格性・契約条件を自動判定したものではない。

| 仮定 | 初期値 |
|---|---:|
| 個人・通常所得の追加税負担率 | 30% |
| 法人・通常所得実効税負担率 | 30% |
| 個人・短期譲渡益合算税率 | 40% |
| 個人・長期譲渡益合算税率 | 20% |
| 消費税率 | 10% |
| 建物取得価額に対する年次概算償却率 | 5% |
| 土地/建物台帳がない場合の建物取得価額割合 | 60% |
| M3における事業床面積 | 60% |
| M3建物の事業供用期間割合 | 100%（推計仮定） |
| 宿泊・賃貸・共通費用のVAT課税仕入取引割合 | それぞれ100%、編集可。固定資産税等は0%に設定可能 |
| VATの仕入税額控除の有効割合 | 100%、編集可 |
| 各課税主体の消費税登録状態 | 初期は「登録なし」仮定。主体ごとに変更可能 |
| 所得税・譲渡税の国税先払い割合 | 65%／77%（残額は住民税相当として分割） |

これらを少しずつ変更した**Base／Upside／Downside**のNPV/IRRや税負担を比較し、特に前提変化にどれほど脆弱かを示す。

### 架空のM3＋M4試算の主要検算（前提依存）

- 個人M3の宿泊割当180日・見込宿泊54泊・共有経費240,000円、事業床面積60% → 共通費の所得税上の按分21,304.109589...円。
- 建物台帳600,000円×年率5% → 総減価額30,000円、事業用償却18,000円、土地の償却0円。
- 売却総額1,200,000円、売却費10,000円、取得原価1,000,000円－建物全体の概算減価額30,000円 → 譲渡益220,000円。個人短期譲渡税率を40%とした**仮の税額88,000円**（法定計算ではない）。
- 初期投資CF0 −1,100,000円、2026年税引前CF2,598,000円。登録なし想定で仕入VAT支払（個人24,000円＋法人1,200円）を控除し、税金を2027/2028年に反映。
- M3を課税事業者とする場合、宿泊売上VAT108,000円を追加現金回収、税込共通費VAT24,000円を支払い、申告で利用可能と**仮定する**控除額2,130.410959...円。翌年の消費税納税CFで差引精算。
- 売却後に納税CFが負となり、IRRが複数符号反転になるケースでは**IRR単一表示をやめ、NPVで比較**する。

## 5. 未対応と今後の優先順

**優先度高：実際の投資意思決定のため**
1. よく使う費目（OTA、光熱、保険、管理費、固定資産税、改修・FF&E）を簡易入力できるフォームとVAT課税仕入割合プリセット。
2. 保有中の建物償却・借入返済・売却手取と入出金を画面上で検算できる年度別ウォーターフォール。
3. 住宅宿泊180日割当・ADR・稼働率・原価率・売却価格の上下感応度、Base／Upside／Downside比較・意思決定ログ・仮定JSONの再利用。
4. 経費・VATの仮定が重なる二重計上を防ぐ各費目の検証。

**精度改善として後回し**
- 申告用の税制証拠、請求書・実予約の完全同期、特例・非業務用償却の厳密計算、領収書・VATインボイス確認、自治体ごとの支払期限、税法個別条項の完全再現。
- 正式JSON Schemaによるブラウザimport、旧v1からの明示移行、アクセシビリティ／実ブラウザE2Eは**製品化として別途必要**だが、概算財務分析機能を試すための税制申告精度のハードゲートとはしない。

## 6. 非破壊性

- 本実装は`develop/v1.1-foundation`のみ。公開`main`と`index.html`は変更しない。
- 税務計算方式は**概算／詳細税務検証の排他的2経路**。税額を二重適用しない。
- 保存正本のv1.1仕様は変更しない。概算前提は独立JSONのインポート／エクスポートで再利用（自動永続保存は行わない）。
- 既存の審査済みGate Bテストを残し、数値を試算しただけで税務適格性の受入完了としない。
