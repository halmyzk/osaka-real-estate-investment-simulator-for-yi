## 2. v1.1専用保存

保存キーは `premium_re_investment_v11` **のみ**。現行公開v1の `osaka_premium_stay_v3` / `_v2` / `_v1` にアクセスしない。

- JSON importはパース→バージョン・主体／住戸ID・参照・カレンダーの日数・シナリオ上書き・主要メタデータ検査→**検査成功後**に下書きを置換。失敗時は現在の下書きを変更しない。
- 未完成の収支入力や`null`は保存を許容。ただし欠損値を「税額0円」や「収益0円」に変換しない。
- 保存は明示ボタンで行い、書込後の同一キーの読戻しが一致した場合だけ成功表示。失敗時は可能な範囲で元の値へロールバックする。
- JSON書出しはバックアップ用。読込の包括的なJSON Schema/Draft 2020-12検証は**ブラウザにはまだ実装していない**。CIのPython版Schema検証とは区別する。
- 税額側ファイルは**保存正本へ混入させず、一時的に読み込む方式**。課税年度・事業前提が変わると再計算対象になる。

## 3. 税引前→所得税等控除後（参考）CF

`compileV11IncomeTaxSidecar`が必要とする側ファイル：

- `version:"v11-income-tax-sidecar-1"`、`scenarioId`、`documentFingerprint`、`taxBasis:"externallyReviewedScenarioAssumption"`、`vatTreatment:"notConnected"`。
- 全投資主体×全保有暦年について、投資あり／投資なしの両ケースに**明示的な税額（ゼロも含む）**、税目、ルール版、直接確認可能なソースURL、納付月を要求。
- 個人は所得税・住民税、購入物件のある個人は譲渡所得税をさらに要求。法人は法人税とその他法人地方税の双方が必要。
- 二つの反実仮想で税額のルール・納付月が違う場合、境界不整合として保留。税務資料の`documentFingerprint`は対象入力が編集されると一致しなくなる（ただしこれは**誤用防止用ハッシュであって電子署名ではない**）。
- 消費税をこの側ファイルから受入れない。還付も税額差分から自動で確定しない。課税売上・VATの税込／税抜の監査は次段階。

数式：

```text
IncrementalIncomeTaxCash[e,m] =
  -(CashPaidWithProject[e,m] - CashPaidWithoutProject[e,m])
PostIncomeTaxReferenceCF[t] =
  PreTaxEquityCF[t] + sum(IncrementalIncomeTaxCash[e,m] in year t)
```

この`PostIncomeTaxReferenceCF`は「所得税等控除後**参考**」であって、**VATや償却・各種課税調整まで反映した最終の税引後Equity CFではない**。

### 架空例：大阪M3（個人）＋東京M4（法人）のBase

| 項目 | 独立期待値 |
|---|---:|
| 初期CF0 | -1,120,000円 |
| 2026年税引前CF | +2,648,000円 |
| 2026年分の外部仮定・増分所得税／住民税／譲渡税／法人関連税の合計 | 77,000円 |
| 2027年の外部仮定・納税差額CF | -74,500円 |
| 2028年1月の外部仮定・納税差額CF | -2,500円 |
| 合計増分所得税等CF | -77,000円 |
| 正式税引後NPV・IRR | **算定保留（null）** |

なお、税額側ファイルの「国税庁URL」は関連税目の**一般的な資料出典**であり、架空の具体的税額77,000円を国税庁が計算したことを意味しない。

## 4. ブラウザ開発画面の確認方法

開発ブランチのリポジトリルートで：

```sh
python3 -m http.server 8000
```

`http://localhost:8000/preview/v11-dev.html` を開く。

1. 03「収支分析」で税引前のCF0、月次営業、年次CF、参考NPV/IRRを確認。
2. Appendix→「架空のBase税額資料を読込む」を**明示操作**。2027・2028年の納税差額が年次CF欄に表れ、所得税等控除後参考NPVを表示。
3. 03でADR等を変更し、前提ハッシュ不一致による所得税側ファイルの無効化を確認。新税額なしでゼロと扱わない。
4. Appendixから下書きを明示保存し、復元、JSONバックアップ／復帰を試す。旧v1を変更しない。
5. 03「税務計算用元帳」で法人・個人の収益と営業費、売却代金、借入と利息を別区分で確認。**課税所得は未算定**。

現時点のブラウザ操作確認は**ソース／NodeテストとJSON Schema CIの検証**であり、複数ブラウザ・レスポンシブ・スクリーンリーダーでの実機受入は未了。

- CIはこれらと従来のNode/Python/正式JSON Schemaサンプル検証を継続。

**次工程をゲート化する**：

1. 保存／輸入：ブラウザでの**完全**JSON Schema検証、シナリオ差分編集UI、バージョンアップ／旧v1インポートプレビューと明示確定、ブラウザE2E。
2. 税額算定：現在の監査用元帳に、資産台帳・税務簿価／事業用割合、利息、用途別課税所得、VAT別の税額区分を**実データから一意に導出**するルートを追加する。
3. 所得税・法人税：年度ルール、控除・欠損金・源泉等の反実仮想を実税務ルールから算定。税引後の仮定適格性・計算範囲を明示して接続する。
4. 総合受入：複数主体・複数住戸・全月次/暦年・契約途中開始／売却後納税まで実ブラウザで検算。Gate A/B/C/Dの受入完了後、別途公開承認。

**今回の進展は保存操作と税額CFの「実行経路」を作ったこと。税務計算と本番アプリの完成を意味しない。**
