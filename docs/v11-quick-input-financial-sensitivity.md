# v1.1 主要費目クイック入力・個別感応度（概算投資判断）

更新日：2026-10-14 JST
対象ブランチ：`develop/v1.1-foundation`
承認された優先順位：税務申告の詳細再現よりも、主要経営条件を直接入力して投資判断の概算NPV/IRRを迅速に比較する。

## 1. 今回の実装

| 操作 | v1.1への保存先 | 投資家CFでの処理 | VAT・税務の仮定 |
|---|---|---|---|
| OTA手数料率（%） | `units[].fields.H.H08` | 宿泊室料売上に対する率から月別宿泊運営費を算定。別のOTA expense lineは**生成しない** | 事業用宿泊経費。課税仕入比率は概算側で変更可 |
| 共通光熱費（月額） | `units[].expenses[]` category `propertyOperating`, `description="[quick:utilities]..."` | 各月に現金費用1件。M3の概算所得控除は事業用床面積×宿泊見込泊数／暦日数 | VAT課税仕入率はproperty欄に従う |
| 保険料（月額換算） | 同 `[quick:insurance]` | 月別現金費用。M3の経費控除は床面積×建物事業供用期間 | VAT対象外とする簡易仮定 |
| 固定資産税（月額換算、購入物件のみ） | 同 `[quick:propertyTax]` | 月別現金費用。M3の経費控除は床面積×建物事業供用期間 | VAT対象外 |
| 宿泊運営・管理委託（月額） | `expenses[].category="lodgingOperating"` | 宿泊営業費（GOP計算に一度だけ計上） | 宿泊運営費の課税仕入率に従う |
| 賃貸管理料（月額） | `expenses[].category="rentalOperating"` | 賃貸営業費 | 賃貸運営費の課税仕入率に従う |
| 改修・FF&E投資 | `units[].assets[]` category `buildingEquipment` / `leaseholdImprovement`, `fields.K.K01` | 対象月の**設備投資CF**に1回のみ計上。初期月の支出はCF0、それ以降は該当年度ICF | 法定減価償却・売却時税務簿価の評価は**概算税額から未控除**。二重に営業費用へ入れない |

今回の簡易明細は保存済みv1.1正式JSONデータ形状に追加する。公表しているv1の入力項目・データには接触しない。`src/v11-quick-input.mjs`のAPIは**原文書を変えず、変換した文書を返す**ため、画面で明示操作したときのみ下書きへ適用する。日付・金額・分類の不正値、ID衝突、対象外の宿泊/賃貸/購入物件費用は入力時に拒否。更新時は同じクイック費目／月の行を置換して増殖させない。

**既存費用の重複について**：H10/H12/R05/R08/A05や手入力 `expenses[]` と、新たなクイック費用は別の入力経路である。同じ請求・同じサービスを両方に計上しないことをUIで告知する。特にM3の既存開発用サンプルには手入力の月次光熱費が存在するため、クイック入力の金額は**置換ではなく追加**として扱われる。一般名・同額だけから他の入力の削除可否を自動決めず、監査可能性を優先する。

## 2. 個別感応度（同じ投資前提）

選択住戸、選択シナリオを基準にした`src/v11-financial-sensitivity.mjs`は元の保存文書のコピー上で、各経営指標を±1〜50%で単独変化させる。

- **ADR**：宿泊`H01`に対し当該住戸のシナリオ値を変更。ホテル以外には適用せず算定不能と表示。
- **宿泊稼働率**：当該住戸の`H02`だけを変更。100%上限を超える不可能な値は拒否する。
- **購入価格**：当該物件の`A01`と土地＋建物の取得原価配分を同比率で動かし、**売却総額は固定**。単なる取得価格の感応度と、売却価格の連動上昇を混同しない。土地・建物台帳が取得費に不一致なら算定拒否。
- **売却価格**：購入価格とCF0を固定し、出口価格の成長率を変更して当該物件の**グロス売却価格のみ**を変動させる。
- 各ケースの概算税引後NPV、基準NPVとの差額、概算IRR（一意に算定できる場合のみ）を提示。
- 比較操作は**元の下書きやシナリオを変更しない**。確定反映には標準入力と経営計画自体の編集が必要。

「Base／Upside／Downsideを税額とともに横比較する従来表」に加え、今回は**原因を一つずつ変える個別感応度**を追加。両表は用途が異なる。

## 3. 限界／完成に向けた範囲

- 事業収益・運営費に対するVAT課税仕入率は入力可能だが、取得時の土地建物・改修CapExに係る仕入税額・償却税効果、持分譲渡、還付適格性等はまだ推計対象外。改修費の現金支出が税引後CFに一度入ることまでは検証した。
- M3は実際の予約泊数の代わりに見込泊数を用いた家事按分シナリオである。保険料・固定資産税・光熱費に同じ係数を掛けず、分類別に按分。
- 年途中改修の貸借対照表、CapExと維持修繕費の税務適格性、資産の残存売却時価値、投資中期の追加借入と累積税損失は簡易モデルの外。
- 長期資産保有や法定端数、価格感応度による税率適用の変更等は**投資判断上の不確実性**として示す。申告の正確さを保証しない。
- 費目フォームの画面内追加・表示とJSON保存経路は接続した。正式公開前には**実ブラウザE2E・モバイル確認・自動移行の安全性／操作性・一部費目の二重計上検知強化**が必要。

## 4. テスト

`tests/v11-quick-financial-ui.test.mjs` は、原本の非変更、費目更新時の重複抑止、実際の投資CFとの一致、M3の費目別家事按分・非課税仕入、初月改修CF0と中途改修ICF、税引後NPVの購入／売却価格別感応度、画面の操作IDを独立検証。

既存のGate A/Bテストと保存データSchema検証をCIで並行実行している。本件は**概算モードの実装が進んだという意味であり、Gate Bの申告税務受入24項目を完了扱いにしたものではない**。
