# v1.1 統合マイルストーン：開発専用プレビュー

日付：2026-10-13

## 目的と今回の技術的到達点

これまでは月次GOP・NOI、金融CF、ポートフォリオIRR/NPV、税額計算が個別モジュールに分かれていた。今回、承認済みGate Dの**実際のv1.1 JSON Schema**から月次営業・資金繰り・税引前投資評価を直接呼び出す限定的なルートを作成した。

- `src/v11-field-resolver.mjs`：`scenario override > calendar field > unit/entity/portfolio field > documented default > incomplete` の入力優先順位。ポートフォリオ`Pxx`と主体`Exx`はそれぞれ`fields`直下、住戸は`fields.H.H01`のようにグループ分けする**正式Schema構造**に対応。
- `src/v11-preview-engine.mjs`：住戸ごとの月次用途、ADR／賃料、占有率％→小数、初年度の宿泊立上げ係数、毎年の名目売上／費用成長、営業費用／借上賃料、取得・造作／家具CapEx・ローン・売却・敷金精算、法人／個人の主体単位での税引前投資CF集計。
- `preview/v11-dev.html`：**開発用・非公開**の4タブ簡易UI（01設計／02前提・根拠／03収支分析／Appendix）。住戸の標準数値を下書き変更、シナリオ選択、税引前CF0/IRR/NPV、年次CF、月次配分、計算保留理由を表示。
- `preview/v11-sample.json`：実際のv1.1 Draft 2020-12スキーマに合格する、架空の個人M3購入＋法人M4賃借の2主体・2住戸データ。Base、Upside、Downside切替。
- **従来の公開アプリ `index.html` と `main` を変更しない**。開発HTMLは別ファイルに保管し、旧localStorageキーを読み書きしない。

## 手動確認する場合（ローカル静的サーバー）

開発ブランチをチェックアウトしたリポジトリのルートで次を実行：

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/preview/v11-dev.html` を開く。通常の `file://` 直開きでは ES modules / fetch の制限により動かないことがある。

1. 01タブで架空の2事業主体と2住戸を確認。
2. 03タブでBase・Upside・Downsideを変更。ADR・稼働率・賃料等の変更と再計算を確認。
3. Appendixで**v1.1専用キー`premium_re_investment_v11`に明示保存**、復元、JSON書出し・読込を検証。旧v1 JSONを無変換で取り込むことは禁止。
4. 02タブは入力の根拠分類と日付／URLを確認。市場観測とサンプル仮定を混同しない。

ブラウザ画面を使う手動E2E・アクセシビリティ確認はまだ行っておらず、今後の受入課題。

## 計算境界・未対応の入力を無視しない設計

- M4は全月の賃貸可能日数を実暦から導出、M2/M3は各住戸の180日枠を個別確認。
- 本プレビューでは取得・営業開始日を月初、売却日を月末に限定。それ以外を日割り推計で誤計算せず拒否。実装本体で任意日付対応が必要。
- CF0はベース月の取得支出／初期CapEx／敷金支払／借入実行に限定。**ベース月の売却代金・敷金返還・売却時の残債完済は年1CF**。同月中の前後関係は本版ではモデルの概算上の限定。
- 資産明細なしの内装総額 `K01`、非対応の高額項目、法人／個人の異主体間所有・運営・費用帰属、分割契約期・特殊出口・ローン繰上返済等は確認不足として計算保留/エラー。
- P04（税引前プレビュー上の割引率）が未設定の場合、NPVのみ算定保留。初期投資がない場合などIRRの計算不能は既存Gate A方式で扱う。
- 売上P05と費用P06の年次増加率は12か月ごとの**名目フィールド計算**にのみ対応。賃料改定条項・月別費用請求・インフレの二重上乗せは行わない。
- **全納税主体の税引後評価を`incomplete`**とし、個別税務ロジックが存在していても、取引別・年度別で正式連結されるまでは税引後IRR/NPVを表示しない。
- 実際の税込現金受払／消費税納税CFは本プレビューの税抜簡易CFと未接続。現金計算が実務申告精度とは異なることを明示。

3. **税務モジュールの本接続**：税額・資産減価・所得区分・源泉税・VAT明細から、支払時点の実CFまで一意にマッピングし、with/withoutの差額を計算して税引後NPV/IRRを有効化。
4. **独立受入**：Gate A/Bに加えてGate C/Dと旧v1互換性をE2E検算。正式な数値レビュー・税務未対応の表示判定が完了するまで公開しない。
5. **公開承認は別途**：開発完了と公開承認を別ゲートとする。

**注意：今回の4タブは最小限の開発プレビューであり、Gate Dの本番画面完成やv1.1のリリースを意味しない。**


## NPV割引率の厳密な表示区分
- Gate Cの `P04` は**税引後自己資本割引率**であり、税引前キャッシュフローに適用したNPVを正式な税引後NPVと誤認しない。
- 本開発プレビューが表示する`referenceDiscountRateBasis`および「参考NPV」は、同一P04を税引前CFに機械適用した**感応度参考値のみ**。数値を税引後投資判断の結論として扱わない。
- 正式UIでは、税引後税額・納付タイミングの算出後、**P04を税引後Equity CFへ適用した正式NPV**を独立計算する。税引前NPV表示が必要なら別の妥当な割引率入力を設計・明示する。
