# v1.1 Foundation (開発ブランチのみ)

設計元: docs/v1.1-design-change-spec.md 第13–16章。Gate Dの実装第1工程として **完全構造スキーマのベース**、型付きフィールド辞書、独立期待値フィクスチャを実装した。計算エンジンと公開UIは未実装。

- `schema/v1.1.schema.json`: Draft 2020-12。住戸・法人/個人・税務ルール・月次用途・経費明細・内装資産・借入・出口・差分シナリオ。 `$defs.fieldsP/U/A/K/F/H/R/S/E/X/SC`にフィールドID・型・単位を固定。メタデータを持つ値は`field`型で保存。
- `schema/field-registry.json`: ID→型・単位・グループの機械可読索引（税務年度別の税率はGate Bルール別に保持）。
- `tests/fixtures/v1.1-financial-cases.json`: **投資収益計算エンジンとは独立した算術期待値**。利益・CF・IRR・NPV・税務按分・複数住戸・出口等。
- フィクスチャは単体・中間値とストーリーを固定し、複雑な法人社宅税額については入力未確定の段階で**偽の期待税額を設定せずblocker**として明記。
- `schema/v1.1.schema.json`はJSON Schema形式上の型・基礎必須を検証し、**意味検証が別途必要**：存在しないEntity参照、ID重複、用途日数合計と閏年、M2/M3暦年180日、年度末税納付、IRRの多重解、同一人物の期間重複（実日付情報がある場合）、領域別フィールドID、スコープごとのオーバーライド、出典不整合、M1–M4および購入/賃借の条件付き必須、税務ルール適用条件。
- 完全な固定スキーマでは既知の項目型が一意に読めるが、条件付きモデル適合・複雑税務の適用可否をJSON Schema単独で証明するものではない。
- 出典と入力は正本、計算結果スナップショットは非正本。旧`osaka_premium_stay_v3/v2/v1`は絶対に上書きしない。新キー`premium_re_investment_v11`は実装工程2以降に扱う。
- 将来の受入試験：Gate A～D全件、加えてJSON Schema実バリデータによるpositive/negativeフィクスチャ、計算独立期待値の照合。アプリ実装完了／公開完了の宣言は不可。
