# v1.1 Gate B：M3購入物件の宿泊・自己居住併用税務の統合（開発用限定モデル）

記録：2026-10-14 JST
ブランチ：`develop/v1.1-foundation`（`main`、公開`index.html`への変更なし）
到達点：**M3の宿泊日数・見込宿泊泊数・共通費用・減価償却・非業務用の譲渡取得費調整を、元データから納税CFまで一貫して検算できる限定経路**。税務上の個別適格性・VAT・正式税引後NPV/IRRの受入は未了。

## 1. 実装の重要な区分

| 日数/金額 | 税務・経営上の使い道 | 本モジュール |
|---|---|---|
| 宿泊営業の**割当日数** | M3の年間180日上限と用途表。実際に宿泊売上が発生した泊数とは異なる | `unit.calendar[].lodgingDays`、`validateAnnualLodgingAllocation` |
| 稼働率から推計した**宿泊相当泊数** | 共通光熱費の暫定按分根拠。予約台帳の実績値ではない | `operating[].result.lodging.soldRoomNights`、年度別審査前提と照合 |
| **事業用面積比率** | 宿泊利用の事業部分と個人の居住部分の分離 | 年度別に`businessFloorArea / totalFloorArea`を明示 |
| **建物事業供用期間** | 建物の事業用償却按分。宿泊180日や宿泊見込泊数を自動代用しない | 年度別`businessSupplyDays / calendarDays`を明示 |
| 共通光熱費の業務用割合 | 事業面積比率 × 宿泊見込泊数比率（本モデルの**独立審査済み推計仮定**） | `allocateBusinessExpense(method:"areaGuestNights")` |
| 建物の事業用償却割合 | 事業面積比率 × 建物事業供用期間比率（本モデルの**独立審査済み推計仮定**） | `allocateBusinessExpense(method:"areaBusinessPeriod")` |
| **売却取得費を減額する業務・非業務用の減価相当額** | 所得計算の必要経費とは必ずしも一致しない。独立して審査した**月次減価相当額**を要求 | `reconcileConcurrentUseSaleBasis` → `landBuildingSaleGain` |

### なぜ売却時の取得費を通常の償却費から逆算しないか
国税庁 No.3261は建物の譲渡所得計算で償却費相当額を取得費から控除する旨を示し、業務・非業務で取扱いが異なる。非業務用部分の法定減価相当額を面積率や180日枠から機械推測して税額を確定することはしない。

売却処理の入力`ownedReview.disposalBasisReview.monthlyRecords`は、取得から売却までの**毎月**について、`businessShare`、`privateShare`、`businessGrossEquivalent`、`nonbusinessGrossEquivalent`、`businessActualDeducted`、`reviewedDisposalTreatment`、`evidenceUrl`を要求する。収益費用から算定した年次の事業用減価償却控除額と、レビュー済み月次の`businessActualDeducted`を整合確認する。**非業務用の法定減価額そのものは別途準備が必要である。**

### 家事按分の実務上の未決事項
- 実予約／実宿泊泊数が取得できる場合は、モデルからの**予測稼働率**による宿泊見込泊数を観測値に置き換え、根拠を保存してから再計算する。
- 月次光熱費と固定資産税・管理費を同じ面積×泊数で一律配分しない。本限定モデルは**明細化した共通光熱費のみ**を受け付け、保有コスト`A05`や分類外費用は算定保留とする。
- M3の自己居住併用での居住用財産特例（3,000万円控除等）は**一切自動適用しない**。売却損・「90%以上非業務」の法的選択も未対応。
- 事業用部分の独立空間・営業供用365日という想定はサンプル上の**審査が必要な入力仮定**であり、M3の全物件の法的事業利用期間を365日と認定したものではない。
- 法人の役員社宅・自己居住はこの個人所有M3モジュールとは別モデルとする。

## 2. 限定実装の対象と拒否条件

対象：**個人所有・個人運営M3**、1月1日取得／事業開始、12月31日売却、土地1資産＋建物1資産、追加改装・取得諸費用なし、年次宿泊枠／自己居住カレンダーを全月入力、年度別面積・供用期間・宿泊見込泊数をレビューし、事業用償却率・非業務用の譲渡時取得費減額は独立審査明細で提示する。

次の場合は `incomplete` を返す：

- 費用が専用光熱費以外で分類・課税上の取扱い未確認、各費目に対して単一の宿泊日数係数を無条件で適用。
- 年度レビュー不足、営業カレンダー・月次の重複・不足、180日枠超過、稼働率から得た見込泊数とレビュー資料の不一致。
- 土地・建物の取得費不一致、資産別償却ルール未審査、事業用面積の不一致、建物私用処理が未設定。
- 非業務用減価相当額の月次証拠不足／異なる按分率／当期償却控除との不整合、未審査の「非業務90%以上」例外。
- 居住用財産特例を自動選択、売却損を自動損益通算、物件取得諸費用・設備投資・改修支出を放置、VATの課税・非課税受払の未接続。
- 所有主体が法人または別の事業体の場合は、このM3個人モジュールで処理しない。

`afterTax`は**依然として`null`**。別途の所得税等控除後指標は、外部仮定・法定適格性レビューが残るため`afterIncomeTaxSensitivity`（参考）と明示する。

## 3. 架空の独立検算

`preview/v11-m3-mixed-use-sample.json` と、編集前提に紐づく`preview/v11-m3-mixed-tax-plan.json`を使う。

| 項目 | 架空シナリオ値 | 検算・備考 |
|---|---:|---|
| M3の年間宿泊割当 | 180日 | 毎月15日×12 |
| M3の年間稼働見込相当 | 54泊 | 15日×50%×初年度立上げ60%×12、**180日ではない** |
| 面積 | 事業60㎡／合計100㎡ | 私用の40㎡を別扱い |
| 暦年日数／建物供用日数 | 365日／365日 | 事業部分の通年供用という**入力仮定** |
| 共通光熱費（現金全額） | 240,000円 | 月20,000円×12、CFに一度計上 |
| そのうち業務用光熱費 | 21,304.109589…円 | 240,000×60%×54/365、概算 |
| 建物取得税務原価 | 600,000円 | 土地は400,000円 |
| 建物の減価償却総額（仮定年率5%） | 30,000円 | 非現金 |
| 建物の当期必要経費控除（仮定） | 18,000円 | 30,000×60%×365/365 |
| 月次の独立レビューによる業務用取得費減額 | 18,000円 | 毎月1,500円×12 |
| 月次の独立レビューによる非業務用取得費減額 | 12,000円 | 毎月1,000円×12、**法定額は別審査の仮定** |
| 建物の売却時調整後取得費 | 570,000円 | 600,000−18,000−12,000 |
| 土地＋建物の売却時取得費 | 970,000円 | 土地40万円は非償却 |
| 売却代金／売却費用 | 1,200,000円／10,000円 | 現金と同じ値 |
| 税務譲渡益 | **220,000円** | 1,200,000−10,000−970,000 |
| 個人短期譲渡税（概算） | **87,186円** | 税率適格性・付加税・納付時期の審査済みとした架空算例 |
| ポートフォリオ初期CF0 | **−1,100,000円** | M3購入100万円＋法人M4敷金10万円 |
| 2026年税引前投資CF | **2,598,000円** | M3営業108万円−光熱費24万円、売却純額119万円、法人M4営業46.8万円＋敷金戻し10万円 |

別の一次資料による按分値の比較（`tests/v11-m3-mixed-tax.test.mjs`）：

```text
240,000円 × (60㎡ / 180㎡) × (実宿泊 90泊 / 365日)
= 19,726.027397... 円 （円単位四捨五入で 19,726円）
```

**確認すべき差異**：建物の減価償却に宿泊90泊／365日を掛けて自動控除しない。また、光熱費に180日宿泊枠を入れると誤って2倍近く計上し得る。

## 5. なお残る本実装

1. 年度・月別の実宿泊泊数実績、面積・事業供用の実際の区分、家事用電気／水道と保険・固定資産税等の**費目別**詳細登録UI。
2. 不動産取得費用、建物附属設備・造作・家具、家事按分が年度途中で変化する場合／開業・売却月が途中の場合の月次配賦。
3. 複雑な不動産売却時の法定非業務減価相当額を年次規則から正しく算定し、家屋私用90%超や居住用財産の特例適格性を独立レビューする。
4. 宿泊売上の税込受領・経費仕入区分・免税課税・入力税額控除・消費税精算と、法人役員の住宅利用を連結し、純粋な税引後Equity CFを確定する。
5. 正式JSON Schemaによるブラウザimport、非破壊旧v1移行、UI全入力、実ブラウザE2E、Gate A/B/C/Dの総合受入と公開承認。
